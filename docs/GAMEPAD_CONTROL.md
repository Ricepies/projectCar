## 1. PS2 Protocol & Hardware Architecture

The Sony PlayStation 2 controller communicates over a synchronous, full-duplex bit-banged SPI protocol (Mode 3: Clock idles `HIGH`, data is shifted on transition):

| Signal Name | Arduino / Code Label | Direction | Description |
| :--- | :--- | :--- | :--- |
| **DATA / DAT** | `MOSI` (GP12) | Controller $\rightarrow$ Pico | Input data line containing button and joystick states. |
| **COMMAND / CMD** | `MISO` (GP13) | Pico $\rightarrow$ Controller | Output command line sending query packets to the gamepad. |
| **ATTENTION / CS** | `CS` (GP14) | Pico $\rightarrow$ Controller | Chip Select line. Must be pulled `LOW` to initiate a frame. |
| **CLOCK / CLK** | `SCK` (GP15) | Pico $\rightarrow$ Controller | Synchronous clock line generated by the Pico (idles `HIGH`). |

### Packet Frame Layout (9 Bytes)
Every polling cycle exchanges a 9-byte stream:
- **Byte 0:** `0x01` (Header start command from host).
- **Byte 1:** `0x42` (Poll command from host). Gamepad responds with ID mode (`0x73` for Red/Analog mode, `0x41` for Digital mode).
- **Byte 2:** `0x5A` (Ready signal acknowledging data follows).
- **Byte 3:** Digital Buttons Byte 1 (Select, L3, R3, Start, Up, Right, Down, Left). **Active LOW (0 = Pressed, 1 = Released)**.
- **Byte 4:** Digital Buttons Byte 2 (L2, R2, L1, R1, Triangle, Circle, Cross, Square). **Active LOW (0 = Pressed, 1 = Released)**.
- **Byte 5:** Right Analog Stick X-axis (`RX`: 0–255, center ~128).
- **Byte 6:** Right Analog Stick Y-axis (`RY`: 0–255, center ~128).
- **Byte 7:** Left Analog Stick X-axis (`LX`: 0–255, center ~128).
- **Byte 8:** Left Analog Stick Y-axis (`LY`: 0–255, center ~128).

### Low-Level Bit-Banging: `ReadData(u8 command)`
This method sends 1 byte to the gamepad while simultaneously reading 1 byte back, LSB-first.

```cpp
14: u8 Gamepad::ReadData(u8 command) {
15:     u8 res = 0;
16:     u8 j = 1;
```
- **Lines 14–16:** `res` will accumulate the 8 incoming bits. `j` is a bitmask initialized to `1` (`0b00000001`) that shifts left each iteration to place received bits at the appropriate power of 2.

```cpp
18:     for (u8 i = 0; i < 8; i++) {
19:         if (command & 0x01) {
20:             digitalWrite(MISO, HIGH);
21:         } else {
22:             digitalWrite(MISO, LOW);
23:         }
24:         command >>= 1;
```
- **Lines 18–24:** Evaluates the least-significant bit (LSB) of `command`. If `1`, drives `MISO` `HIGH`; if `0`, drives `MISO` `LOW`. Shifts `command` right by 1 to prepare the next bit for subsequent iterations.

```cpp
26:         delayMicroseconds(10);
27:         digitalWrite(SCK, LOW);
28:         delayMicroseconds(10);
```
- **Lines 26–28:** Asserts clock pulse LOW. The PS2 controller samples the `MISO` command line on the falling edge of `SCK`. The 10 microsecond delays provide the required setup and hold times for the receiver's internal shift register.

```cpp
30:         if (digitalRead(MOSI) == HIGH) {
31:             res += j;
32:         }
```
- **Lines 30–32:** Samples the `MOSI` data line driven by the controller. If `HIGH`, adds `j` (`1 << i`) to `res`, reconstructing the incoming byte.

```cpp
34:         j <<= 1;
35:         digitalWrite(SCK, HIGH);
36:         delayMicroseconds(10);
37:     }
```
- **Lines 34–37:** Shifts `j` left by 1 (e.g., `1` $\rightarrow$ `2` $\rightarrow$ `4` $\rightarrow$ `8`). Pulls `SCK` back `HIGH` to complete the clock pulse.

```cpp
39:     digitalWrite(MISO, HIGH);
40:     delayMicroseconds(50);
41:     return res;
42: }
```
- **Lines 39–42:** Restores `MISO` to idle `HIGH`. Waits 50 microseconds to allow the receiver controller to process the received byte before returning the 8-bit response `res`.

```cpp
63:     }

```
- **Lines 59–64:** Decodes button press states:
  - Iterates through all 16 buttons.
  - PS2 protocol uses **inverted logic (Active LOW)**: a pressed button is represented by a `0` bit, while an unpressed button is `1`.
  - `(1U << (MASK[index] - 1))` creates a bitmask for the target button.
  - If the bitwise AND results in `0`, the button is currently physically pressed, and `dynamicButtonStatus[index + 1]` is set to `true`.

- **Lines 72–76:** Normalizes the raw byte into a percentage range (**-100 to +100**):
  - **Horizontal Axes (`LX`, `RX`):** 
    - Full Left: `(0 - 128) * 100 / 127 = -100`
    - Center: `(128 - 128) * 100 / 127 = 0`
    - Full Right: `(255 - 128) * 100 / 127 = +100`
  - **Vertical Axes (`LY`, `RY`):**
    - PS2 hardware outputs `0` when pushed forward and `255` when pulled backward.
    - `(255 - data)` inverts this axis so that **Pushing Forward = Positive (+100)** and **Pulling Backward = Negative (-100)**, matching standard robotic Cartesian coordinates.

```cpp
84:         lastPressed[button] = millis();
85:         return true;
86:     }
87:     return false;

```

  - If satisfied, updates `lastPressed[button]` to current time and returns `true`.
  - Prevents rapid re-triggering while holding the button (e.g. for toggle actions like arming motors).

## 5. Differential Kinematics & Joystick Mixing

The Left Stick drive algorithm computes individual wheel speeds via differential mixing:

$$\begin{aligned}
\text{Speed}_{\text{Front-Left}} &= \text{ly} + \text{lx} \\
\text{Speed}_{\text{Front-Right}} &= \text{ly} - \text{lx} \\
\text{Speed}_{\text{Rear-Left}} &= \text{ly} + \text{lx} \\
\text{Speed}_{\text{Rear-Right}} &= \text{ly} - \text{lx}
\end{aligned}$$

### Operating Modes:
1. **Full Forward (`ly = +100, lx = 0`):**
   - Left side: $100 + 0 = 100$
   - Right side: $100 - 0 = 100$
   - $\rightarrow$ Car drives straight forward at full power.
2. **Full Reverse (`ly = -100, lx = 0`):**
   - Left side: $-100 + 0 = -100$
   - Right side: $-100 - 0 = -100$
   - $\rightarrow$ Car drives straight backward at full power.
3. **Spin Turn Left (`ly = 0, lx = -100`):**
   - Left side: $0 + (-100) = -100$ (Reverse)
   - Right side: $0 - (-100) = +100$ (Forward)
   - $\rightarrow$ Car rotates counter-clockwise in place.
4. **Arc Turn Forward-Right (`ly = +100, lx = +50`):**
   - Left side: $100 + 50 = +150 \rightarrow$ Clamped to $+100$ by `Motor::run()`
   - Right side: $100 - 50 = +50$
   - $\rightarrow$ Left wheels turn faster than right wheels, carving a smooth right curve.
